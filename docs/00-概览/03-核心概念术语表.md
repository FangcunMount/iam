# 核心概念术语表

## 30 秒结论

IAM 的难点不是接口数量，而是概念边界。最重要的区分是：

- `User` 是稳定身份主体。
- `Principal` 是认证成功后的运行时主体。
- `Subject` 是授权域中的主体引用。
- `ProfileLink` 是身份关系，不是权限。
- `RoleBinding` 是授权事实，不是登录身份。

## 术语表

| 术语 | 所属模块 | 定义 |
| --- | --- | --- |
| User | Identity | IAM 内部稳定身份主体 |
| Profile | Identity | 业务身份资料、档案或被服务对象 |
| ProfileLink | Identity | User 与 Profile 的关系事实 |
| LoginIdentity | AuthN | User 绑定的登录身份，如 username、phone、wechat openid |
| Credential | AuthN | 长期认证材料，如 password hash |
| Challenge | AuthN | 短期认证挑战，如短信 OTP |
| Principal | AuthN | 认证成功后的运行时主体表达 |
| Session | AuthN | 服务端认证上下文 |
| AccessToken | AuthN | 客户端访问资源携带的短期凭证 |
| RefreshToken | AuthN | 用于续期 AccessToken 的凭证 |
| Subject | AuthZ | 授权主体引用，常见为 `user:<id>` |
| Resource | AuthZ | 受保护资源 |
| Action | AuthZ | 对资源执行的动作 |
| Scope | AuthZ | 授权范围约束 |
| Role | AuthZ | 权限集合 |
| Permission | AuthZ | Role 对 Resource/Action/Scope 的声明 |
| RoleBinding | AuthZ | Subject 持有 Role 的事实 |
| WechatApp | IDP | 外部微信应用配置和凭据聚合 |
| ProfileSearchTerm | Suggest | Profile 联想搜索索引项 |
| ProfileAccessScope | Suggest | 当前操作员可见 Profile 范围 |

## 常见误区

- 不把 User 当成 Principal 或 Subject。
- 不把 ProfileLink 当成 Permission。
- 不把 Casbin facts 当成 AuthZ 领域语言。
- 不把微信 openid 当成 Credential。
- 不把 Suggest 当成 Identity 写模型。
