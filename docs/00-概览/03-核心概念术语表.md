# 核心概念术语表

> 状态：已实现 · 术语定义与当前领域模型、契约和运行时语义已复核；概念性扩展均显式标注。

---

## 1. 本文回答

本文回答 4 个问题：

- IAM 中最核心的概念分别是什么意思？
- Identity、AuthN、AuthZ、IDP、Suggest 各自拥有哪些术语？
- 哪些概念最容易混淆？
- 后续阅读业务模块文档时，应该如何使用这些术语？

本文是概览层术语表，只定义系统级语言。具体模型字段、状态流转和关键链路见 [02-业务模块](../02-业务模块/README.md)。

---

## 2. 30 秒结论

IAM 的难点不是接口数量，而是概念边界。

最重要的 8 个区分是：

```text
User 是稳定身份主体，不是 Principal，也不是 Subject。
Principal 是认证成功后的运行时主体，不是数据库里的 User。
Subject 是授权域中的主体引用，不是 User 本体。
Profile 是业务身份资料或被服务对象，不等于 User。
ProfileLink 是 User 与 Profile 的身份关系事实，不是 Permission。
LoginIdentity 是登录身份，不是 Credential。
IDP 只提供外部身份来源证明，不创建 IAM 登录态。
Casbin 是 infra runtime，不是 AuthZ 领域语言。
```

如果只记一句话：

> Identity 讲身份事实，AuthN 讲认证事实，AuthZ 讲授权事实，IDP 讲外部身份来源，Suggest 讲 Profile 联想搜索读模型；跨模块协作必须通过清晰术语表达，不能把一个模块的对象偷换成另一个模块的对象。

---

## 3. 术语分组总览

| 模块 | 核心术语 | 主要回答的问题 |
| --- | --- | --- |
| Identity | User、Profile、ProfileLink | 用户是谁，用户和业务档案是什么关系 |
| AuthN | LoginIdentity、Credential、Challenge、Principal、Session、AccessToken、RefreshToken、JWKS | 如何证明用户身份，认证成功后如何表达 |
| AuthZ | Subject、Resource、Action、ObjectAttribute、Role、Assignment、RoleInheritance、PermissionGrant、ConstraintSet、AuthorizationDecision、PolicyVersion | 用户能访问什么 |
| IDP | WechatApp、Credentials、AppToken、ExternalIdentity | 外部身份来源如何接入 |
| Suggest | ProfileSearchTerm、ProfileAccessScope、ProfileSuggestionIndex、ProfileSuggestItem | 如何快速搜索可见 Profile |
| Access | REST、gRPC、Go SDK | 业务系统如何接入 IAM |
| Guard | Architecture Test、Contract Test、SDK Compile Test、Docs Hygiene | 如何防止代码、契约、文档漂移 |

## 4. Identity 术语

Identity 是身份事实中心。

它的术语围绕 `User / Profile / ProfileLink` 展开。

| 术语 | 定义 | 不是什么 |
| --- | --- | --- |
| User | IAM 内部稳定身份主体，用于表达系统内部“这个用户是谁” | 不是登录身份，不是运行时 Principal，不是授权 Subject |
| Profile | 业务身份资料、业务档案或被服务对象 | 不是 User 本体，不负责登录，也不表达权限 |
| ProfileLink | User 与 Profile 之间的身份关系事实 | 不是 Permission，不是 RoleBinding，不是登录态 |

### 4.1 User

`User` 是 IAM 内部稳定身份主体。

它用于回答：

```text
系统内部这个人是谁？
其他模块应该通过什么稳定 ID 引用这个人？
多个登录身份最终应该归属到哪个内部用户？
```

常见边界：

```text
User 可以被 AuthN 通过 UserID 引用；
User 可以被 AuthZ 映射成 Subject；
User 可以通过 ProfileLink 关联 Profile；
User 不直接表达登录态；
User 不直接表达权限。
```

---

### 4.2 Profile

`Profile` 是业务身份资料、业务档案或被服务对象。

它用于回答：

```text
这个用户关联了哪些业务档案？
业务系统真正服务的对象是谁？
管理端搜索、选择、操作的业务档案是什么？
```

常见边界：

```text
Profile 不等于 User；
Profile 不负责登录；
Profile 不负责权限；
Profile 可以被 Suggest 消费用于构建读模型；
Profile 和 User 的关系由 ProfileLink 表达。
```

---

### 4.3 ProfileLink

`ProfileLink` 是 `User` 与 `Profile` 之间的身份关系事实。

它用于回答：

```text
某个 User 和某个 Profile 是否有关联？
是什么关系？
关系什么时候建立？
关系是否已撤销？
```

常见边界：

```text
ProfileLink 是身份关系，不是授权关系；
ProfileLink 不是 Permission；
ProfileLink 不是 RoleBinding；
ProfileLink 的存在不必然意味着可以访问所有资源；
是否能访问资源仍由 AuthZ 判断。
```

---

## 5. AuthN 术语

AuthN 是认证域。

它的术语围绕 `LoginIdentity / Credential / Challenge / Principal / Session / Token` 展开。

| 术语 | 定义 | 不是什么 |
| --- | --- | --- |
| LoginIdentity | User 绑定的登录身份，用于定位 User | 不是 Credential，不是 Token，不是 User 本体 |
| Credential | 长期认证材料，例如 password hash | 不是 LoginIdentity，不是短信验证码，不是微信 openid |
| Challenge | 短期认证挑战，例如短信 OTP | 不是长期凭据，不是 Session，不是 Token |
| Principal | 认证成功后的运行时主体表达 | 不是 User 数据库实体，不是 AuthZ Subject 本体 |
| Session | 服务端认证上下文 | 不是 AccessToken，不是 RefreshToken |
| AccessToken | 客户端访问资源时携带的短期访问凭证 | 不是 Session，不是长期凭据 |
| RefreshToken | 用于续期 AccessToken 的续期凭证 | 不应交给资源服务，不是 AccessToken |
| JWKS | 公钥发布机制，用于资源服务本地验签 | 不是认证策略，不是授权策略 |

### 5.1 LoginIdentity

`LoginIdentity` 是 User 绑定的登录身份。

它用于回答：

```text
用户可以通过什么身份登录？
这个外部或内部登录标识最终指向哪个 User？
同一个 User 是否可以绑定多个登录身份？
```

示例：

```text
username；
phone；
wechat openid；
wecom userid。
```

常见边界：

```text
LoginIdentity 用于定位 User；
Credential 用于证明请求者控制 LoginIdentity；
一个 User 可以有多个 LoginIdentity；
LoginIdentity 不是密码 hash；
LoginIdentity 不是 AccessToken。
```

---

### 5.2 Credential

`Credential` 是长期认证材料。

它用于回答：

```text
请求者如何证明自己控制某个 LoginIdentity？
系统应该如何保存可长期校验的认证材料？
认证材料是否可锁定、过期或失效？
```

常见示例：

```text
password hash。
```

当前文档不要把未核对落地的能力写成已实现。例如 passkey、TOTP、recovery code 等如果没有代码事实支撑，应标记为 `规划改造` 或不写入当前事实。

常见边界：

```text
Credential 是认证材料；
LoginIdentity 是登录身份；
Challenge 是短期认证挑战；
微信 openid 更接近外部身份标识，不是 Credential 本身。
```

---

### 5.3 Challenge

`Challenge` 是短期认证挑战。

它用于回答：

```text
短信验证码、一次性验证码等短期挑战如何表达？
挑战目标是什么？
什么时候过期？
是否已被消费？
```

常见边界：

```text
Challenge 是短期事实；
Credential 是长期认证材料；
Challenge 不应该被当成 Session；
Challenge 成功后可以参与认证，但不等于登录态。
```

---

### 5.4 Principal

`Principal` 是认证成功后的运行时主体表达。

它用于回答：

```text
当前请求者是谁？
这次认证使用了什么方法？
认证结果应该如何传递给后续链路？
```

常见边界：

```text
Principal 不是 User 数据库实体；
Principal 通常包含 UserID、LoginIdentityID、AuthMethod、AMR 等认证上下文；
Principal 可以被资源服务或应用层使用；
进入 AuthZ 时，Principal 通常需要转成 Subject 或参与构造 Subject。
```

---

### 5.5 Session

`Session` 是服务端认证上下文。

它用于回答：

```text
某次登录或认证上下文是否仍然有效？
RefreshToken 是否仍然绑定在有效认证上下文上？
需要撤销某次登录时，服务端应该撤销什么？
```

常见边界：

```text
Session 是服务端状态；
AccessToken 是客户端携带的短期凭证；
RefreshToken 是续期凭证；
Session 可以被撤销，Token 也可以被吊销，但三者不是同一个对象。
```

---

### 5.6 AccessToken

`AccessToken` 是客户端访问资源时携带的短期凭证。

它用于回答：

```text
资源服务如何识别调用者？
请求是否在有效期内？
Token 是否由可信签名方签发？
```

常见边界：

```text
AccessToken 通常是短期凭证；
AccessToken 不应保存密码、RefreshToken、私钥或完整用户资料；
AccessToken 可以通过 JWKS 被资源服务本地验签；
AccessToken 不等于 Session。
```

---

### 5.7 RefreshToken

`RefreshToken` 是续期凭证。

它用于回答：

```text
AccessToken 过期后，客户端如何获取新的 AccessToken？
续期是否仍然绑定在有效 Session 上？
RefreshToken 是否被撤销或轮换？
```

常见边界：

```text
RefreshToken 不应交给普通资源服务；
RefreshToken 不等于 AccessToken；
RefreshToken 应由 AuthN token endpoint 控制；
RefreshToken 的生命周期通常长于 AccessToken。
```

---

### 5.8 JWKS

`JWKS` 是公钥发布机制。

它用于回答：

```text
资源服务如何拿到验签公钥？
Token 签名密钥如何支持轮换？
kid 如何帮助资源服务选择正确公钥？
```

常见边界：

```text
JWKS 解决验签公钥发布问题；
JWKS 不解决授权判定问题；
JWKS 不代表在线认证状态检查；
Token 本地验签通过，不必然代表业务授权通过。
```

---

## 6. AuthZ 术语

AuthZ 是授权域。

它的术语围绕 `Subject / Resource / Action / ObjectAttribute / Role / Assignment / RoleInheritance / PermissionGrant / ConstraintSet / Decision` 展开。

| 术语 | 定义 | 不是什么 |
| --- | --- | --- |
| Subject | 授权主体引用，例如 `user:<id>` | 不是 User 数据库实体，不是 Principal 本体 |
| Resource | 受保护资源 | 不是接口路径本身，接口只是资源的一种暴露方式 |
| Action | 对资源执行的动作 | 不是 HTTP method 的简单同义词 |
| Scope | 授权范围约束 | 不是 Role，不是 Resource |
| Role | 权限集合或权限聚合点 | 不是用户身份，不是登录身份 |
| PermissionGrant | Role 对 Resource / Action / ConstraintSet 的 allow 声明 | 不是 ProfileLink，不是 Assignment |
| RoleBinding | Subject 持有 Role 的授权事实 | 不是 LoginIdentity，不是 ProfileLink |
| AuthorizationDecision | 权限检查结果 | 不是权限配置本身 |
| PolicyVersion | 授权事实版本 | 不是业务数据版本，不等于 exactly-once 保证 |
| Outbox | 事务内记录待发布事件的机制 | 不是消息队列本身，不等于 exactly-once |

### 6.1 Subject

`Subject` 是授权域中的主体引用。

它用于回答：

```text
这次授权检查针对谁？
授权系统应该用什么格式引用调用者？
```

常见形式：

```text
user:<userID>
service:<serviceID>
```

常见边界：

```text
Subject 不是 User 本体；
Subject 可以引用 User；
Principal 可以被转换或映射为 Subject；
AuthZ 不维护 User 写模型。
```

---

### 6.2 Resource

`Resource` 是受保护资源。

它用于回答：

```text
权限系统保护的对象是什么？
某个操作要访问什么资源？
资源如何被稳定标识？
```

常见边界：

```text
Resource 不是接口路径本身；
REST/gRPC endpoint 可以映射到 Resource；
Resource 应该表达业务资源，而不是只表达传输层路由。
```

---

### 6.3 Action

`Action` 是对资源执行的动作。

它用于回答：

```text
Subject 想对 Resource 做什么？
读取、创建、更新、删除、管理等操作如何表达？
```

常见边界：

```text
Action 不等于 HTTP method；
HTTP GET 可以映射为 read，也可能是 search/export 等更具体动作；
Action 应服务授权语义，而不是机械复制接口方法。
```

---

### 6.4 Scope

`Scope` 是授权范围约束。

它用于回答：

```text
这条权限在哪个租户、组织、项目、Profile 范围内有效？
是否需要限制资源实例或数据范围？
```

常见边界：

```text
Scope 不是 Role；
Scope 不是 Resource；
Scope 用于限制 Permission 生效范围；
Scope 也可能影响查询可见范围。
```

---

### 6.5 Role

`Role` 是权限集合或权限聚合点。

它用于回答：

```text
一组 Permission 如何被命名和复用？
某类用户通常拥有哪些能力？
```

常见边界：

```text
Role 不是用户身份；
Role 不是 LoginIdentity；
Role 本身不直接说明谁拥有它；
谁拥有 Role 由 RoleBinding 表达。
```

---

### 6.6 Permission

`PermissionGrant` 是 Role 对 Resource / Action / ConstraintSet 的 allow 声明。

它用于回答：

```text
某个 Role 允许对哪些 Resource 执行哪些 Action？
这些能力在哪些 Scope 下有效？
```

常见边界：

```text
Permission 是授权能力声明；
ProfileLink 是身份关系事实；
Permission 不应该表达 User 和 Profile 的身份关系；
Permission 通常挂在 Role 上。
```

---

### 6.7 RoleBinding

`RoleBinding` 是 Subject 持有 Role 的授权事实。

它用于回答：

```text
谁拥有某个 Role？
这个 Role 在什么 Tenant 或 Scope 下生效？
绑定是否仍然有效？
```

常见边界：

```text
RoleBinding 不是 LoginIdentity；
RoleBinding 不是 ProfileLink；
RoleBinding 是授权事实，不是身份关系；
对外 wire term 可以叫 Assignment，但内部领域术语应使用 RoleBinding。
```

---

### 6.8 AuthorizationDecision

`AuthorizationDecision` 是权限检查结果。

它用于回答：

```text
这次 Check 是否允许？
为什么允许或拒绝？
是否命中了某条规则或缺失某类权限？
```

常见边界：

```text
AuthorizationDecision 是检查结果；
Permission 和 RoleBinding 是授权事实；
Decision 不应该被持久化成权限配置本身。
```

---

### 6.9 PolicyVersion

`PolicyVersion` 是授权事实版本。

它用于回答：

```text
某个授权域下的策略事实变化到了哪个版本？
运行时策略是否已经加载到最新授权事实？
权限变更如何触发 reload 或同步？
```

常见边界：

```text
PolicyVersion 是授权事实版本；
PolicyVersion 不是业务数据版本；
PolicyVersion 可以帮助运行时判断是否需要刷新策略；
PolicyVersion 不等于 exactly-once。
```

---

### 6.10 Outbox

`Outbox` 是事务内记录待发布事件的机制。

它用于回答：

```text
授权事实写入和事件记录如何在同一事务中完成？
事务提交后如何异步发布事件？
运行时如何感知授权事实变化？
```

常见边界：

```text
Outbox 不是消息队列本身；
Outbox 不等于 exactly-once；
Outbox 解决的是本地事务内事实与事件记录一致；
事件投递仍需处理重试、幂等和重复消费。
```

---

## 7. IDP 术语

IDP 是外部身份源辅助模块。

它的术语围绕 `WechatApp / Credentials / AppToken / ExternalIdentity` 展开。

| 术语 | 定义 | 不是什么 |
| --- | --- | --- |
| WechatApp | 微信应用配置聚合 | 不是 LoginIdentity，不是 User |
| Credentials | 外部应用密钥材料或密钥引用 | 不是 IAM Credential，不是用户密码 |
| AppToken | 外部平台 access token | 不是 IAM AccessToken |
| ExternalIdentity | IDP 完成 provider code exchange 后产出的请求级、已验证且不可变的标准外部身份证明 | 不是外部标识字符串、LoginIdentity、IAM User 或 Session |

### 7.1 WechatApp

`WechatApp` 表示微信类外部应用配置。

它用于回答：

```text
要调用哪个微信应用？
appid、secret 或密钥引用如何治理？
应用属于哪个 provider 或 realm？
```

常见边界：

```text
WechatApp 是外部应用配置；
LoginIdentity 是 IAM 登录身份；
WechatApp 不等于 LoginIdentity；
WechatApp 不拥有 User。
```

---

### 7.2 Credentials

`Credentials` 在 IDP 语境中表示外部应用密钥材料或密钥引用。

它用于回答：

```text
调用外部身份源需要什么密钥？
密钥如何存储、引用、轮换？
```

常见边界：

```text
IDP Credentials 是外部应用凭据；
AuthN Credential 是用户认证材料；
两者术语相近，但所属模块和语义不同；
文档中必须说明上下文，避免混用。
```

---

### 7.3 AppToken

`AppToken` 是外部平台 access token。

它用于回答：

```text
IAM 调用外部平台 API 时使用什么 token？
外部 token 如何缓存和刷新？
```

常见边界：

```text
AppToken 是外部平台 token；
IAM AccessToken 是 IAM 签发给客户端访问资源的凭证；
AppToken 不能当成 IAM 登录态。
```

---

### 7.4 ExternalIdentity

`ExternalIdentity` 是 IDP 在完成 provider code exchange 后产出的请求级、已验证且不可变的值对象。它由 `provider + realm + 受限 identifiers + verifiedAt` 组成，当前覆盖微信小程序、微信开放平台和企业微信；不会携带 code、AppSecret、provider token、原始响应或 IAM UserID。

它用于回答：

```text
本次 provider proof 被哪个 provider/realm 验证？
openid、unionid、userid、open_userid 等标识如何按 provider 不变量表达？
外部身份如何交给 AuthN 绑定或登录？
```

常见边界：

```text
ExternalIdentity 不是 IAM User；
ExternalIdentity 不是持久化 LoginIdentity，也不是可重放 Credential；
ExternalIdentity 由 AuthN 映射为认证输入或 LoginIdentity ProviderKey；
外部身份被证明后，IAM 登录态仍由 AuthN 创建。
```

---

## 8. Suggest 术语

Suggest 是 Profile 联想搜索读模型。

它的术语围绕 `ProfileSearchTerm / ProfileAccessScope / ProfileSuggestionIndex / ProfileSuggestItem` 展开。

| 术语 | 定义 | 不是什么 |
| --- | --- | --- |
| ProfileSearchTerm | Profile 搜索索引项 | 不是 Profile 主事实 |
| ProfileAccessScope | 当前操作员可见 Profile 范围 | 不是通用授权策略，不是 Permission |
| Snapshot | Suggest 索引快照或运行时数据版本 | 不是 Identity 数据主表 |
| ProfileSuggestItem | 联想搜索返回结果 | 不是 Profile 完整详情 |

### 8.1 ProfileSearchTerm

`ProfileSearchTerm` 是 Profile 联想搜索索引项。

它用于回答：

```text
哪些关键词可以召回某个 Profile？
姓名、拼音、手机号尾号等搜索词如何组织？
索引项如何支持快速 autocomplete？
```

常见边界：

```text
ProfileSearchTerm 是读模型索引项；
Profile 主事实仍属于 Identity；
索引项可以重建，不能替代 Profile 写模型。
```

---

### 8.2 ProfileAccessScope

`ProfileAccessScope` 是当前操作员可见 Profile 范围。

它用于回答：

```text
当前操作员可以搜索哪些 Profile？
搜索结果需要按哪些组织、项目、角色或关系过滤？
```

常见边界：

```text
ProfileAccessScope 是 Suggest 查询范围约束；
它不是通用授权策略；
它不替代 AuthZ 的 Permission / RoleBinding；
它可以消费 AuthZ 或 Identity 的事实来构造可见范围。
```

---

### 8.3 Snapshot

`Snapshot` 是 Suggest 索引快照或运行时数据版本。

它用于回答：

```text
当前进程内索引基于哪个版本的数据？
索引刷新后如何切换运行时快照？
出现异常时如何降级或回退？
```

常见边界：

```text
Snapshot 是读模型运行时概念；
它不是 Identity 的数据主表；
Snapshot 可以被重建；
Snapshot 不拥有 Profile 主事实。
```

---

### 8.4 ProfileSuggestItem

`ProfileSuggestItem` 是联想搜索返回结果。

它用于回答：

```text
用户输入关键词后，系统返回哪些候选？
结果中展示哪些脱敏字段？
命中了哪个搜索词？
```

常见边界：

```text
ProfileSuggestItem 不是 Profile 完整详情；
ProfileSuggestItem 应遵守脱敏和权限范围；
ProfileSuggestItem 不应该泄露不可见 Profile。
```

## 9. Access 与 Guard 术语

### 9.1 Access 术语

Access 是接入形态，不是业务模块。

| 术语 | 定义 | 不是什么 |
| --- | --- | --- |
| REST | 面向前端、管理端、调试或部分业务接入的 HTTP API | 不是领域模型 |
| gRPC | 面向服务间调用的 RPC 契约 | 不是领域模型 |
| Go SDK | 面向 Go 业务服务接入 IAM 的产品化封装 | 不是业务层，不是事实源本身 |
| OpenAPI | REST 机器契约事实源 | 不是叙述性文档 |
| proto | gRPC 机器契约事实源 | 不是叙述性文档 |

常见边界：

```text
REST/gRPC/SDK 是接入方式；
业务模型仍在 Identity/AuthN/AuthZ/IDP/Suggest；
字段、路径、RPC 以机器契约为准；
文档只解释契约如何使用，不复制完整契约。
```

---

### 9.2 Guard 术语

Guard 是架构与契约护栏，不是业务模块。

| 术语 | 定义 |
| --- | --- |
| Architecture Test | 检查分层依赖、模块边界、禁止依赖等架构规则 |
| Contract Test | 检查 REST/gRPC 契约与实现的一致性 |
| SDK Compile Test | 检查 Go SDK public API 是否可被业务方稳定使用 |
| Docs Hygiene | 检查文档链接、旧术语、archive 事实回流等问题 |

常见边界：

```text
Guard 不定义业务事实；
Guard 保护业务事实和接入契约不漂移；
Guard 是工程治理能力，不是业务模型本身。
```

## 10. 高频混淆概念对照

### 10.1 User / Principal / Subject

| 概念 | 所属模块 | 定位 | 生命周期 |
| --- | --- | --- | --- |
| User | Identity | 稳定身份主体 | 长期存在 |
| Principal | AuthN | 认证成功后的运行时主体表达 | 随认证上下文产生 |
| Subject | AuthZ | 授权主体引用 | 随授权判定使用 |

关键区分：

```text
User 是身份事实；
Principal 是认证结果；
Subject 是授权引用。
```

错误写法：

```text
Principal 就是 User。
Subject 就是 User。
AuthZ 直接维护 User。
```

推荐写法：

```text
AuthN 认证成功后产出 Principal。
Principal 中的 UserID 可以映射为 AuthZ Subject。
AuthZ 通过 Subject 引用 User，不拥有 User 写模型。
```

---

### 10.2 LoginIdentity / Credential / Challenge

| 概念 | 所属模块 | 定位 | 示例 |
| --- | --- | --- | --- |
| LoginIdentity | AuthN | 登录身份 | username、phone、wechat openid |
| Credential | AuthN | 长期认证材料 | password hash |
| Challenge | AuthN | 短期认证挑战 | SMS OTP |

关键区分：

```text
LoginIdentity 说明“用什么身份登录”；
Credential 说明“如何长期证明控制这个身份”；
Challenge 说明“如何通过短期挑战证明一次控制”。
```

错误写法：

```text
openid 是 Credential。
短信验证码是 Credential。
Credential 就是 LoginIdentity。
```

推荐写法：

```text
wechat openid 可以成为 LoginIdentity 的外部标识。
password hash 是 Credential。
短信验证码是 Challenge。
```

---

### 10.3 ProfileLink / Permission / RoleBinding

| 概念 | 所属模块 | 定位 |
| --- | --- | --- |
| ProfileLink | Identity | User 与 Profile 的身份关系事实 |
| PermissionGrant | AuthZ | Role 对 Resource / Action / ConstraintSet 的 allow 声明 |
| RoleBinding | AuthZ | Subject 持有 Role 的授权事实 |

关键区分：

```text
ProfileLink 说明“这个用户和这个档案有什么关系”；
Permission 说明“某个角色有什么能力”；
RoleBinding 说明“某个主体拥有哪个角色”。
```

错误写法：

```text
用户和孩子有关联，所以这就是权限。
ProfileLink 就是 Permission。
RoleBinding 是用户关系。
```

推荐写法：

```text
ProfileLink 是身份关系事实。
是否能访问某个资源，仍由 AuthZ 的 Permission / RoleBinding / Check 判定。
```

---

### 10.4 IDP AccessToken / IAM AccessToken

| 概念 | 所属模块 | 定位 |
| --- | --- | --- |
| IDP AppToken | IDP | IAM 调用外部平台 API 时使用的外部 access token |
| IAM AccessToken | AuthN | IAM 签发给客户端访问资源的短期凭证 |

关键区分：

```text
IDP AppToken 是 IAM 访问外部平台的凭证；
IAM AccessToken 是客户端访问 IAM/业务资源的凭证。
```

错误写法：

```text
微信 access_token 就是 IAM AccessToken。
外部 access token 可以当作 IAM 登录态。
```

推荐写法：

```text
IDP 使用外部 AppToken 调用微信/企微 API。
AuthN 使用 IAM AccessToken 表达客户端访问凭证。
```

---

### 10.5 Casbin Model / AuthZ Domain Model

| 概念 | 所属层 | 定位 |
| --- | --- | --- |
| AuthZ Domain Model | domain/application | Subject、Resource、Action、ObjectAttribute、Role、Assignment、RoleInheritance、PermissionGrant、ConstraintSet |
| Casbin Model | infra runtime | 策略匹配执行引擎和 matcher 表达 |

关键区分：

```text
AuthZ 领域模型是业务语言；
Casbin 是运行时策略匹配工具；
不能把 Casbin facts 当成全部领域语言。
```

错误写法：

```text
AuthZ 领域模型就是 p/g facts。
权限系统就是 Casbin CRUD。
```

推荐写法：

```text
AuthZ 使用领域模型表达授权事实。
infra/casbin 将授权事实投影到 Casbin runtime 进行匹配。
```

### 11.1 必须统一使用的术语


### 11.2 禁止写成当前事实的旧说法

```text

User 就是 Principal；
User 就是 Subject；
ProfileLink 就是 Permission；
RoleBinding 是登录身份；
openid 是 Credential；
微信 access_token 是 IAM AccessToken；
IDP 负责创建 IAM 登录态；
Suggest 是 Identity 写模型；
Casbin facts 是 AuthZ 领域语言；
_archive 是当前事实源。
```

---

### 11.3 对外术语与内部术语

部分概念在对外契约中可能使用更易理解的 wire term，但内部领域文档应使用领域术语。

| 内部领域术语 | 可能的对外 wire term | 说明 |
| --- | --- | --- |
| RoleBinding | Assignment | 对外可说“角色分配”，内部领域应说 RoleBinding |
| AccessToken | access_token | wire 字段使用 snake_case，领域文档使用 AccessToken |
| RefreshToken | refresh_token | wire 字段使用 snake_case，领域文档使用 RefreshToken |
| Subject | subject / sub | token 或 API 中可能用 subject/sub，语义要按上下文区分 |
| Resource | resource | API 字段可同名，但领域定义以 AuthZ 文档为准 |

## 15. 本文总结

IAM 术语体系的核心是 5 组边界：

```text
Identity：User / Profile / ProfileLink；
AuthN：LoginIdentity / Credential / Challenge / Principal / Session / Token；
AuthZ：Subject / Resource / Action / ObjectAttribute / Role / Assignment / RoleInheritance / PermissionGrant / ConstraintSet；
IDP：WechatApp / Credentials / AppToken / ExternalIdentity；
Suggest：ProfileSearchTerm / ProfileAccessScope / ProfileSuggestionIndex。
```

最重要的判断是：

```text
User 不是 Principal，也不是 Subject；
ProfileLink 不是 Permission；
LoginIdentity 不是 Credential；
IDP AppToken 不是 IAM AccessToken；
Casbin 是 infra runtime，不是 AuthZ 领域模型；
Suggest 是读模型，不是 Identity 写模型。
```

术语统一是后续业务模块文档、专题设计和宣讲材料的基础。任何概念进入现行文档前，都必须先判断它属于哪个模块、表达什么事实、不能替代哪个相邻概念。
