# 架构风格与设计原则

> 状态：待补证据 · 骨架初稿，待与代码/契约核对。

## 30 秒结论

IAM 使用分层架构和 Ports & Adapters，把业务规则、用例编排、协议适配和基础设施实现分开。

```text
cmd/apiserver
  -> internal/apiserver/process
  -> internal/apiserver/container
  -> transport/rest + transport/grpc
  -> application
  -> domain
  -> infra
```

## 设计原则

- `main` 保持薄，只负责启动命令。
- `process` 管生命周期、配置和资源关闭。
- `container` 是组合根，负责模块装配。
- `transport` 只做协议适配、DTO、错误映射。
- `application` 负责用例编排和事务边界。
- `domain` 只表达业务规则和端口。
- `infra` 实现数据库、Redis、Casbin、JWT、微信 API、Suggest Runtime 等外部能力。
