# 概览

> 状态：已实现 · 本入口组织当前系统定位、术语、架构原则和跨模块统一模型。

IAM 的五个职责中心是：

```text
Identity：内部身份事实
AuthN：认证、Session 与 Token
AuthZ：资源授权
IDP：外部身份源接入
Suggest：Profile 联想搜索读模型
```

建议按这条路径建立完整心智模型：

1. [IAM系统定位：交付事实、接入路径与责任边界](01-IAM系统定位.md)：用家长档案、员工转店和有限搜索区分身份、登录、能力、范围与最终业务接受。
2. [模块划分与协作关系：事实、事务与运行责任](02-模块划分与协作关系.md)：通过注册、停用、赋权、展示和搜索区分事实所有者、调用端口、提交与任务责任。
3. [核心概念术语表：名称、来源与可证明的边界](03-核心概念术语表.md)：通过同名Subject/Scope/Version、身份阶段与投影辨析，说明每个名字来自哪里、还能缺什么检查。
4. [架构风格与设计原则](05-架构风格与设计原则.md)：分层、端口、事务和运行时原则。
5. [跨模块统一模型](06-跨模块统一模型.md)：事实、证明、决策、投影与三种转换。
6. [运行时](../01-运行时/README.md) 与 [业务模块](../02-业务模块/README.md)：进入实现。

如果只记一条边界：Identity 维护“谁”，AuthN 证明“当前是谁”，AuthZ 判断“能做什么”；IDP 和 Suggest 分别提供外部身份适配与派生搜索能力，不能吞并前三者的事实。

定位篇还分开本地/在线用户验证、mTLS服务调用者和业务对象，说明字段校验、实际安全配置及各载体恢复责任。五模块不是五服务，核心/辅助分组也不等同DDD战略领域或启动关键等级；未实施扩展列出新合同、成本和接受样本。

协作篇明确窄端口与共享仓储/数据库并存：注册的外层事务、存在性与active准入、资料保存后展示失败、晚到撤销及独立搜索投影各有成功边界；替换方案必须先定义提交、版本与任务所有者合同。

术语篇按身份、核验、凭证、授权、时间/版本和外部/派生模型组织定义；区分Challenge记录与明文code、字段提取与验签、实际能力与入口准入。流程回链模块主文，术语定义不替代当前环境与业务接受。
