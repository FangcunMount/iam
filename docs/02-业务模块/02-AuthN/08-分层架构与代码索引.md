# AuthN 分层架构与代码索引

> 状态：已实现 · 本文提供 AuthN 从契约到组合根的责任地图，并说明常见改动必须穿过哪些层。

## 1. 分层主线

```text
REST / gRPC
  -> application/signup | linking | signin | session | token | jwks
  -> domain/loginidentity | credential | challenge | authentication | session
  -> ports
  -> MySQL / Redis / JWT / PEM / WeChat / SMS adapters
  -> container/authn composition root
```

Domain 不依赖 Gin、gRPC、Redis、GORM、微信 SDK；Application 负责编排阶段和事务边界；Infra 实现端口；Transport 只做协议映射；Container 决定运行时选用哪个实现。

## 2. Domain 地图

| 子包 | 责任 | 核心不变量 |
| --- | --- | --- |
| `loginidentity` | provider key 与 User 绑定 | provider/realm/identifier 完整、唯一、状态明确 |
| `credential` | 密码等长期验证材料 | enabled + 未锁定才可用，失败计数与轮换 |
| `challenge` | OTP/OAuth 短期状态 | TTL、scene、消费一次 |
| `authentication` | 多策略认证与 Principal | 证明成功后才产生 Principal |
| `session` | 在线会话与生命周期 | active/revoked/expired、绝对上限 |

## 3. Application 地图

| 用例 | 路径 | 主要依赖 |
| --- | --- | --- |
| SignUp | `application/authn/signup` | AuthN UoW、IDP、hasher |
| Linking/Unlink | `application/authn/linking` | LoginIdentity store、Challenge、IDP |
| SignIn | `application/authn/signin` | selector、proof、authenticator、recorder、token |
| Challenge | `application/authn/challenge` | Redis repository、SMS delivery/quota |
| Session facade | `application/authn/session` | SignIn + Token service |
| Token | `application/authn/token` | JWT codec、Redis stores、Session domain services |
| JWKS | `application/authn/jwks` | key reader/lifecycle/publisher ports |

`signin` 又分 method 与 proof：method 负责公开请求形状选择，proof 负责外部 I/O/一次性状态，领域 authenticator 负责最终验证。

## 4. Infrastructure 地图

| 事实/能力 | 实现 |
| --- | --- |
| LoginIdentity/Credential/User/JWKS metadata | `infra/mysql/...` |
| SignUp transaction | `infra/mysql/uow/authn` |
| Challenge/OTP/Session/Refresh/Revocation | `infra/cache/redis` |
| JWT RS256 | `infra/token/jwt` |
| key lifecycle、PEM、JWKS snapshot | `infra/token/keyset` |
| 微信身份解析 | `infra/wechat`、`infra/wechatapi` |
| 短信 | `infra/sms` |

Redis 中的 Session、refresh token 和索引是认证在线事实，不是普通可丢缓存；清理或不可用策略必须按认证数据处理。

## 5. Transport 与契约

- REST：`transport/rest/authn`，契约 `api/rest/authn.v2.yaml`；
- gRPC：`transport/grpc/service/authn`，契约 `api/grpc/iam/authn/v2/authn.proto`；
- SDK 认证/JWKS：`pkg/sdk/auth`；
- 公开方法 catalog：`application/authn/signin/method`，transport 不应自建另一份列表。

REST 与 gRPC 都通过 container capabilities 装配；实现了 handler 并不代表已经注册，必须检查 `container/authn/rest.go`、`grpc.go` 和最终 registry。

## 6. Composition root

`container/authn/infra.go` 选择 MySQL、Redis、JWT、PEM、IDP、event adapters；`domain.go` 建 Session creator/loader/revoker/lifetime policy；`application.go` 组合全部用例；`rest.go`/`grpc.go` 暴露能力；`scheduler.go` 管理 JWKS 等后台任务。

启动时 JWKS 是硬门槛：active key 数量、有效期、私钥材料与 publish snapshot 任一不满足都会使 AuthN 初始化失败。IDP 未提供微信 adapter 时会装配不可用实现，具体 proof 调用失败，而不是让整个 AuthN 组合根无法构造。

## 7. 常见修改路径

### 新增登录方式

1. `loginidentity.Provider` 与 provider key；
2. application method payload/selector；
3. proof builder 与外部端口；
4. domain authentication strategy；
5. container 注入；
6. REST/gRPC/OpenAPI/proto/SDK；
7. linking/signup 是否支持及其安全语义；
8. strategy、contract、transport、composition tests。

### 修改 Token claims

同时检查 Principal、Session claims、JWT codec、middleware request context、SDK parser、audience/issuer 验证、refresh claims codec 和下游兼容。新增 claim 不能仅改 generator。

### 修改 Refresh 语义

同时检查 token store 原子操作、Session absolute lifetime、replay 行为、并发测试、TTL、logout 和 metrics。不要把 `Get + Delete + Set` 拆成非原子多步。

### 修改 JWKS rotation

同时检查 MySQL 唯一 active guard、PEM material、publishable 状态、grace window、scheduler、ETag/cache、SDK refresh 和备份恢复。

### 修改 User/Identity 状态联动

同时检查在线 `SubjectAccessEvaluator` 与异步 session revocation outbox。前者是请求时 fail-closed，后者是状态收敛，不能只保留其中之一。
