# AuthZ 授权模型与匹配语义

> 状态：已实现 · 本文定义最终领域语义，不使用字符串 Scope 或通用策略 DSL。

## 1. RBAC 与条件的分工

- Role 表达稳定岗位或能力集合。
- Assignment 把 Subject 绑定到 Role。
- RoleInheritance 复用 Role 能力并禁止循环。
- PermissionGrant 把 Role 连接到一个 Resource、一个 Action 和一个 ConstraintSet。
- 业务关系留在拥有事实的业务模块，不复制到 IAM。

一个 Subject 的直接和继承 Role 对应的 Grant 之间是 OR；单个 Grant 的谓词是 AND。任一候选 Grant 完全满足即 allow，否则 deny。

## 2. PermissionGrant

公开管理接口只接受资源目录中的精确资源和单一具体动作。内部 bootstrap/迁移工具可以创建 wildcard，但 wildcard Grant 必须无条件。稳定 `grant_key/hash` 基于规范化内容生成，用于 active 唯一性与迁移核对。

Grant 撤销后不再参与快照构建；改变资源、动作或条件必须创建新 Grant，不能原地覆盖审计事实。

## 3. ConstraintSet v1

```json
{
  "version": 1,
  "all_of": [
    {
      "attribute": "object.origin_type",
      "operator": "EQ",
      "value": {"type": "string", "string": "adhoc"}
    }
  ]
}
```

约束如下：

- 最多八个谓词；首版只支持 `EQ`。
- 值类型为 `string`、`int64` 或 `bool`。
- 属性必须由 Resource 的 AttributeSchema 注册。
- 重复、未知属性、非法枚举值和类型不匹配拒绝写入或 RPC 请求。
- 求值属性缺失是正常 deny，`deny_code=attribute_missing`。
- 空集合表示无条件授权。

## 4. 匹配规则

公开 Resource 是规范四段 key；公开 Action 是具体名称。内部 wildcard 只使用明确的 `*`，不把任意正则当作策略语言。条件 Grant 不得匹配 list、search 或 batch 类动作。

匹配和约束求值位于 AuthZ domain/runtime，不依赖数据库 adapter 或 transport 的字符串技巧。
