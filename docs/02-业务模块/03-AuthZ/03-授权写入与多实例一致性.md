# 授权写入与多实例一致性

> 状态：已实现 · 管理事实、PolicyVersion 和 Outbox 在同一事务提交；运行时只有原生快照。

## 1. 写入事务

Grant/Revoke、Assignment 变更、Role/Resource 变更都通过 AuthZ UnitOfWork：

```text
validate command and invariants
  -> write management facts
  -> increment tenant PolicyVersion
  -> stage iam.authz.version_changed outbox
  -> commit
  -> best-effort local native reload
```

事实、版本或 Outbox 任一步失败，事务整体回滚。提交后 reload 失败不撤销已提交事实；实例保留上一份原生快照并降低 readiness，等待后续事件或重试恢复。

## 2. 多实例传播

Outbox relay 发布版本变化事件，各实例订阅后执行完整 reload。事件只是重新加载提示，不是授权事实。决策响应中的版本始终来自实际已发布的 runtime snapshot，不能使用尚未加载的数据库版本。

## 3. 管理不变量

- Grant 内容规范化后生成稳定 key/hash，active 记录唯一。
- Grant 只可撤销和重建，不可原地修改。
- RoleInheritance 写入同时执行循环检测。
- Resource Schema 变更同样递增策略版本，因为它会改变属性校验和求值。
- public API 不接受 wildcard；内部创建 wildcard 时要求无条件。

## 4. 状态语义

| 状态 | 含义 |
| --- | --- |
| committed | 管理事实、版本和 Outbox 已原子提交 |
| published | relay 已发布版本事件 |
| delivered | 当前实例收到 reload 信号 |
| loaded | 新快照完整构建并原子发布 |

只有 loaded version 能描述当前实例实际使用的授权事实。
