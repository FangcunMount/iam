# AuthZ 模块边界与代码索引

> 状态：已实现 · 本文对应 AuthZ v3、PermissionGrant 和原生 runtime。

## 1. 边界

| 模块 | 拥有的事实 | 与 AuthZ 的关系 |
| --- | --- | --- |
| Identity | User、Profile | AuthZ 只引用稳定主体 ID |
| AuthN | Principal、Session、服务身份 | 提供可信 Subject/Tenant 上下文 |
| AuthZ | Role、Assignment、Inheritance、Grant、Resource Schema | 解析角色并对资源动作和对象属性求值 |
| qs-server | Assessment、组织、Testee、业务状态 | 校验关系，读取 `OriginType()`，调用 v3 Check |
| Suggest | ProfileAccessScope 派生读模型 | 局部查询过滤，不是 AuthZ ConstraintSet |

`ProfileAccessScope` 是 Suggest 自己的查询可见集合，与已退役的 AuthZ 字符串范围没有继承关系。

## 3. 修改规则

- 新对象属性先注册 Schema，再扩展 ConstraintSet 校验和受信调用方 ACL。
- 新 Resource/Action 通过目录和服务端常量注册，不能接受客户端任意策略表达式。
- 新业务关系判断留在业务模块；IAM 只接收稳定、已加载对象的受信属性。
- 对象级入口必须区分候选检查和最终 Check；通用 capability 只认可无条件模式。
- 任何策略写入都必须覆盖 version、Outbox 和 runtime reload 链。
