# AuthZ：直接角色与资源动作授权

> 状态：已实现 · 2026-10-06 对照当前代码修订；历史发布及业务验收另行记录。

AuthZ 管理直接角色、资源动作 Grant 和 Assignment Scope，基于不可变快照判定动作能力，并向业务服务导出权限及配对数据范围。角色继承与对象条件已退役。业务系统继续校验有效身份、公司/门店及对象归属、关系和状态；一次 Check ALLOW 不是数据访问的完整准入证明。

## 接入与维护入口

`ReplaceManagedAssignments` 的受管集合 M 由部署角色白名单确定，不按分配创建者划分；该接口仅处理无范围关系，已有公司范围关系拒绝。公司范围管理使用独立 `ReplaceScopedAssignments` 与期望版本。替换响应的 `direct_roles` 是本次目标受管子集；读取快照的同名字段才按应用过滤。完整退出核对需要受限完整角色及逐 Assignment 事实，详见 [授权写入](03-关键链路-授权写入与受管Assignment.md)。

增量 Grant 创建无 Scope 的分配；按 Subject+Role 撤销覆盖该岗位在全部公司的分配，按 Assignment ID 才定位单条。当前 admin 的 `allow_all` 可做增量写入，但两种公开 Replace 和完整 facts 请求被拒。启动 ACL 交叉检查尚未枚举 Scoped RPC，不能据此推断所有写方法都已覆盖；运行时内容准入仍生效，具体接入限制见 [gRPC 与 SDK](06-关键链路-gRPC服务间授权与SDK.md)。

授权收敛依赖所有投影事实变化都推进全局版本；相同版本只确认，不重读事实。已知target领先、事件ACK、fresh及AuthZ readiness分别有不同含义，默认预算允许短期旧结果，并在读取入口检查；具体失败和恢复时序由[多实例收敛](04-关键链路-多实例策略收敛.md)解释。

PermissionGrant创建是受信策略配置权，当前没有按操作者已拥有能力计算可授予上界；固定敏感Role保护也不替代原始管理动作。查询应用的管理可见性与写应用的动作复核不对称，具体调用责任、DTO默认值和契约偏移由[REST管理](05-关键链路-REST管理与路由授权.md)维护。

当前代码、历史迁移完成、今日事实一致与业务验收是不同结论。残留有效条件 Grant 或非空资源属性模式的数据库不能被当前 Runtime 解释为无条件事实。维护前重新查询清单状态与生效版本，不复用历史人数、SHA 或预演指纹。
