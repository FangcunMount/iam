# Suggest 模块边界、分层架构与代码索引

> 状态：已实现 · Suggest 是策略型查询域；TST/Hash、MySQL、Redis 和 Prometheus 都是可替换 adapter。

## 1. 边界结论

Suggest 的边界不是“所有与 Profile 搜索有关的代码”，而是：

> 从 Identity 事实构建可重建的候选索引，并根据当前 Principal、AuthZ capability 和可见属性，产出安全、稳定、有限的 Profile 联想结果。

它拥有查询语义和派生索引生命周期，不拥有 Profile 主数据、JWT、授权策略或详情读取。

## 2. 跨模块数据所有权

| 数据/决策 | Owner | Suggest 中的形态 | 是否可回写 |
| --- | --- | --- | --- |
| User/Profile/ProfileLink | Identity | MySQL Loader 输入 | 否 |
| 登录主体与 JWT 生命周期 | AuthN | request context 中的 UserID/tenant/org 快照 | 否 |
| Route Permission 与角色闭包 | AuthZ | `AuthorizationFacts` | 否 |
| `SuggestibleProfile` | Suggest domain | 最小派生读模型 | 仅由刷新重建 |
| `Scope`、准入、选择与披露规则 | Suggest domain | 本次查询决策 | 不持久化 |
| TST/Hash Store | Suggest infra | 进程内可丢弃状态 | 只由刷新端口更新 |
| REST envelope | Suggest transport | 对外 DTO | 不进入 domain |

“搜索候选可见”不等于“Profile 详情已授权”。调用方拿到 ID 后，详情接口仍应执行其自己的授权与状态检查。

## 3. 分层依赖

```text
transport/rest/suggest
        |
        v
application/suggest/queryprofile -------> domain/suggest/*
application/suggest/refreshindex -------> domain/suggest/profile
        ^                                      ^
        |                                      |
infra/mysql/suggest ---------------------------+
infra/suggest/authorization ------------------+
infra/suggest/index/memory --------------------+
infra/suggest/visibility ----------------------+
infra/suggest/metrics -------------------------+

container/suggest
  -> maps global options
  -> constructs application + infra
  -> owns startup Full, cron and cleanup
  -> exports transport/runtime capabilities
```

允许的方向是：

```text
transport -> application -> domain
infra -> application ports + domain
container -> application + infra + transport deps
```

禁止的方向包括：

- domain import SQL、Gin、Cron、Prometheus、Redis 或全局 options；
- application import具体 infra、文件系统或 Cron；
- REST suggest 直接 import `infra/suggest`；
- infra adapter 直接读取 `internal/apiserver/options`；
- memory index 直接调用 Prometheus package。

## 7. Container 与 Transport

### 7.1 `container/suggest`

Composition root 负责：

- 把 `SuggestOptions` 映射到 query/memory/loader/visibility/ratelimit 小配置；
- 组装 MySQL reader、AuthZ facts、scope resolver、Runtime 和 Service；
- 执行初始 Full；
- 注册 Full/Delta Cron 与 Cleanup；
- 根据 `required` 选择失败还是 `DegradedQuerier`；
- 向 REST 暴露 Querier、RateLimiter、Metrics；
- 向 cache governance 暴露实际启用的 rate-limit family。

### 7.2 `transport/rest/suggest`

Transport 只负责：

- 注册 `GET /api/v2/suggest/profile`；
- query binding；
- 从 Gin context 构造 Principal；
- handler 边界限流；
- application ResultItem → REST DTO；
- 统一错误和成功 envelope。

路由级 JWT 与 `profiles/search` middleware 在 `internal/apiserver/transport/rest/module_routes.go` 装配，
不在 suggest handler 内硬编码角色。

当前没有：

- Suggest gRPC service；
- Suggest Go SDK；
- 对外刷新管理 API；
- 持久 snapshot 或索引管理 endpoint。

## 8. 配置索引

| 外部键 | 默认/关闭语义 | 内部归属 |
| --- | --- | --- |
| `suggest.enable` | `false` 时不初始化 | container |
| `suggest.required` | `true` 时启动失败阻断服务 | container/readiness |
| `suggest.full_sync_cron` | 空值映射为 `@every 1h` | container |
| `suggest.delta_sync_cron` | 空值关闭 Delta 调度 | container |
| `suggest.max_results` | `<=0` 默认 20 | queryprofile |
| `suggest.internal_max_results` | `<=0` 默认 MaxResults × 10，且不小于 MaxResults | queryprofile |
| `suggest.key_pad_len` | `<=0` 默认 25 | memory adapter |
| `suggest.trie_wildcard_key_cap` | `<=0` 默认 100 | memory adapter |
| `suggest.full_sql` | 空值使用内建 SQL | MySQL adapter |
| `suggest.delta_sql` | 空值使用内建 SQL；是否调度仍由 cron 决定 | MySQL adapter |
| `suggest.loader_placeholder_org_id` | `0` 不虚构 org | MySQL adapter |
| `suggest.visibility_cache_ttl_seconds` | `<=0` 不缓存 | visibility adapter |
| `suggest.disable_mobile_mask` | 默认 false；production 禁止 true | query + container guard |
| `suggest.rate_limit.per_operator_qps` | `<=0` 整体关闭 | ratelimit adapter |
| `suggest.rate_limit.*burst` | 非正时按 QPS 计算默认 | ratelimit adapter |
| `suggest.rate_limit.backend` | 开启后默认 memory，可设 redis | ratelimit adapter |
| `suggest.rate_limit.operator_map_max_entries` | 默认 10000 | memory limiter |

历史 `suggest.data_dir`、`suggest.snapshot` 和 `loader_placeholder_tenant_id` 已删除；options validation 会 fail-closed 拒绝这些旧配置，
而不是静默忽略。

## 11. 接入 Elasticsearch 的正确边界

如果容量、跨实例一致性、重启预热或检索能力证明需要 Elasticsearch，应新增：

```text
infra/suggest/index/elasticsearch
  implements queryprofile.CandidateRecaller
  implements refreshindex.IndexWriter
```

然后在 container 切换 wiring。领域层仍保留 `Keyword`、`Intent`、`Candidate`、`Scope`、`SelectionPolicy` 和披露规则。

只有当 Elasticsearch 必须承担 scope 预过滤或排序下推时，才需要重新设计端口，例如让 recall request 接收可编译的 scope/filter；
不应把 Elasticsearch DSL 泄漏到 domain。迁移还必须处理索引 schema/version、alias 切换、手机号字段加密/访问、批量 rebuild、双读验证和故障降级。

## 12. 当前已知边界

1. 默认 org 是占位值，owner visibility 是 `created_by` 规则。
2. 各实例拥有独立索引 generation，刷新时间可能不同。
3. CandidateBudget 在 scope filter 前截断，可能造成可见结果不足。
4. 没有 snapshot；新实例依赖 MySQL 完成初始 Full。
5. visibility cache 会短暂缓存错误。
6. Redis limiter fail-open，且 fixed window 与 memory token bucket 语义不完全一致。
7. 原始手机号存在于进程内 Hash；heap dump 和诊断访问应按敏感数据治理。
8. optional 启动降级不自动恢复；调度注册失败后的 health 表达仍不完整。
9. OpenAPI 对照脚本只验证顶层 Suggest envelope，没有递归校验 response item。

这些限制应由容量、安全或运维证据驱动后续改造，不应通过增加无行为的 domain 类型掩盖。

## 13. 架构护栏

`internal/pkg/architecture/architecture_test.go` 中的 `TestSuggestProfileSuggestionBoundaries` 固定：

- application 不得依赖 infra/filesystem/cron；
- domain 不得出现 metrics、索引配置、物理 mutation 等技术 token；
- REST 不得依赖 suggest infra；
- application/suggest 根目录不得重新长出 façade；
- 已删除的 `application/suggest/service.go`、`infra/suggest/search` 不得回流；
- memory index 的 metrics 必须通过端口注入；
- infra/suggest 不得 import 全局 options。

`TestSuggestRetiredNumericTenantFieldsDoNotReturn` 另外防止数值 TenantID 再次混入授权域和业务 OrgID 模型。
