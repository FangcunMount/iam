# 文档治理

> 状态：已实现 · 文档解释当前实现，不反向覆盖代码、机器契约或运行证据。

## 1. 事实优先级

```text
current code/runtime
  > machine contracts/config/migrations
  > focused tests and CI evidence
  > active docs
  > archive/history
```

冲突时先修正文档或实现，不通过复制另一篇文档来“投票”。旧文档只提供问题线索，所有结论要回到当前 checkout 重查。

## 2. 每篇设计文档的固定问题

1. 解决什么问题；
2. 责任属于哪个模块；
3. 当前模型/链路怎样实现；
4. 关键不变量和失败语义；
5. 为什么采用当前方案；
6. 可选方案及未采用原因；
7. 当前限制与风险；
8. 代码、契约、配置、迁移和测试证据；
9. 可复制的验证命令；
10. 面试追问与答案。

不要求机械出现十个标题，但必须回答这些问题。只有概念科普、没有 repo 责任链的文章不属于 active source-of-truth docs。

## 3. 状态标签

- 当前事实：已由当前代码/合同确认；
- 设计建议：尚未实现，不能写成现状；
- 运行证据：带环境、版本、时间窗口；
- 验收台账：记录结论和证据引用，不替代正文；
- 历史归档：不可被 active docs 作为当前事实引用。

`TODO`、规划和“未来可以”应放在限制/演进部分，不和当前行为混写。

## 4. Canonical ownership

同一个主题只有一个 canonical 正文：

- 模块模型与链路归 `02-业务模块`；
- 跨模块基础设施归 `03-基础设施`；
- 接口接入归 `04-接口与SDK`；
- 测试、迁移、发布和运维归 `05-工程质量与运维`；
- 跨模块决策摘要归 `06-专题设计`，通过链接回 canonical 细节；
- `07-面试索引` 只编排介绍、案例、追问和公开贡献口径，不拥有技术事实。

面试问答应嵌入最接近的 canonical 文档，独立宣讲材料只做短导航，不能复制数百行事实。

## 5. 自动卫生检查

`make docs-hygiene` 检查 active Markdown 链接、反引号 repo path 和 retired reference；`make docs-facts` 从机器事实生成期望值，除配置、路由、迁移、
事件和 wiring 外，还核对 proto 服务矩阵、授权资源示例、Quick Start 端口、active 文档状态计数、历史提示词归档和个人 Go 路径。

它们不能证明自然语言全部正确。每次模块代码变化仍要沿责任链复核文档，尤其是配置默认值、注册 surface、事务顺序和 failure semantics。

## 6. 删除和归档策略

- Git 已保存历史且旧文档无持续参考价值：直接删除；
- 有审计/决策追溯价值：移入 `_archive` 并在索引标明日期/原因；
- 不用 redirect stub 堆满 active tree；仅在外部链接确实依赖时保留短跳转；
- archive 不参与 current docs 导航，不被正文引用为事实。

## 7. Review 清单

- [ ] 标题和目录归属唯一；
- [ ] 现状与建议分开；
- [ ] 所有 repo path 真实存在；
- [ ] 验证命令使用 `go test` 或 Make target，没有个人 Go 安装路径；
- [ ] contract 名称与 code/display label 未混淆；
- [ ] security claim 有当前配置/代码证据；
- [ ] 验证命令与目标环境明确；
- [ ] 没有长段复制其他文档；
- [ ] 删除/替换后所有导航更新；
- [ ] `make docs-hygiene docs-facts` 通过。
