# 遗留资产、兼容层与数据库退役审计

> 状态：已实现 · 审计与不依赖生产写权限的首批退役已完成；审计基线为 2026-08-07、提交 `41a7d7f3eeb24970d51201f2bc42144db7b92bee`。本文是遗留资产退役的 canonical 台账，不授权直接删除生产数据。

## 1. 结论先行

IAM 的五项仓库内遗留代码已经退役，schema/bootstrap 双真相源也已收敛；历史 MySQL 表、外部兼容和治理缺口仍不能按名字统一处理。

| 结论 | 当前判断 |
| --- | --- |
| 业务模块 | 仍以 3 个核心模块 Identity/AuthN/AuthZ 和 2 个辅助模块 IDP/Suggest 为边界 |
| 已完成代码清理 | AuthZ 根包 facade、旧 Profile Editor、旧 OTP code store、`OrgIDOrDefault`、失效注释和 Makefile 提示均已移除 |
| 必须保留的兼容 | REST `wechat` wire 名、`/health`、历史数值 `tenant_id` 归一、历史事件 payload、Suggest 删除配置 tombstone |
| MySQL 表 | 用户截图中的 25 张表里，14 张是当前运行表，1 张是迁移元数据，4 张是明确历史业务表，6 张没有当前运行时读写适配器 |
| 是否可以立即 DROP | 不可以。仓库静态证据不能证明生产无读写、无外部消费者、回填一致或备份可恢复 |
| 已消除中间态 | bootstrap 的 AuthZ 域已统一为 `fangcun`；静态 schema 快照已移除；迁移链成为 schema 唯一事实源并有门禁 |
| 事件/缓存 | 一般 Outbox backlog 未进入 readiness；Suggest Redis 限流未进入 cache family catalog。这是治理缺口，不是遗留删除项 |
| 审计表 | `audit_logs`、`auth_token_audit` 有 DDL 但无生产 writer，属于未闭合能力，需产品/合规决策后才能保留或删除 |

退役状态只使用以下五类：

| 状态 | 含义 | 当前允许的动作 |
| --- | --- | --- |
| 已完成 | 删除责任链、行为保护、文档与验证已经闭合 | 保留防回流门禁，后续按回归处理 |
| 保留兼容 | 已有调用方、部署或显式兼容测试 | 不删除；补充到期条件和观测 |
| 待生产证据 | 静态证据很强，但缺真实流量/数据/配置证据 | 只做只读预检和观测 |
| 待产品决策 | 删除会放弃尚未闭合的业务/合规能力 | 先确认能力归属和保留期 |
| 治理缺口 | 当前能力的可靠性/可观测性不足 | 独立设计，不混入遗留清理 |

## 2. 审计范围与证据边界

本次按业务和技术两个方向交叉检查：

```text
业务方向
  Identity / AuthN / AuthZ
  IDP / Suggest

技术方向
  REST / gRPC / Go SDK
  composition root / config / deployment
  MySQL / migration / bootstrap
  Redis / cache governance
  event catalog / Outbox / readiness
  tests / architecture guards / cross-repository callers
```

证据包括当前代码、路由注册、OpenAPI/proto、SDK、配置、迁移、脚本、测试、Git 历史和一个本地 MySQL 快照。未取得生产数据库、网关 30 天流量、生产配置指纹、表 I/O、备份恢复和跨服务运行日志，因此本文不能证明任何生产表已经安全可删。

命名中出现 `legacy`、`deprecated` 或 `v1` 只生成候选，不构成删除授权。反过来，没有旧名字的 `schema_version`、`tenants` 等表也可能是遗留资产。

## 6. Schema 与发布链路中的中间态

### 6.1 已发布 migration 可变

当前 000002 自己注明它要桥接旧 `children/guardianships`，因为 000001 在 Identity 重构后被编辑。迁移版本只执行一次；同样的 `schema_migrations.version=2` 可能对应不同物理结构。

本地 `iam_contracts` 快照印证了这一风险：版本为 `2, dirty=0`，但没有 `profiles/profile_links`，仍有 `children/guardianships`。这不证明生产状态，只证明“版本号相同”不能证明“当前文件内容执行过”。

从现在开始必须执行：

- 000001–000018 视为已发布且不可再改；
- 所有修复只新增 forward migration；
- migration acceptance 同时检查 version、列/索引/约束和关键数据，不只检查 `dirty=0`；
- 不通过手改 `schema_migrations` 伪造执行完成。

### 6.2 AuthZ tenant domain 双源冲突

migration 000014 把 `authz_roles.tenant_id`、`authz_assignments.tenant_id`、`authz_policy_versions.tenant_id` 和 `casbin_rule` 中的历史 `"1"` 归一到 `"fangcun"`。

该中间态已消除：`configs/mysql/bootstrap.sql` 的 QS 角色、分配、policy 和策略版本现在只写 `fangcun`。`TestAuthzStandaloneBootstrapUsesCanonicalTenantDomain` 会阻止 AuthZ seed 重新出现 `"1"`；AuthN login identity 的历史 realm 和数据字典数值不是 AuthZ tenant domain，不在这次替换范围。历史 JWT 数值兼容继续由 token 归一层处理。

### 6.3 Schema 唯一事实源

当前只保留两类不同职责的输入：

```text
internal/pkg/migration/migrations/*.sql   schema 唯一事实源
configs/mysql/bootstrap.sql               schema 当前后可执行的幂等基线数据
```

没有真实执行入口且已与 migration 终态漂移的静态 schema 快照已经删除。`configs/mysql/README.md` 记录职责，`scripts/check-docs-facts.py` 同时阻止静态副本回归和 bootstrap 混入 DDL。`make db-bootstrap` 保留，但只能在应用完成 migration 且 `schema_migrations` clean 后使用。

## 7. 事件、缓存与审计的邻接问题

这些问题在排查中发现，但不应伪装成“删遗留代码”一并处理。

| ID | 发现 | 风险 | 分类 |
| --- | --- | --- | --- |
| GOV-EVENT-001 | DB 存在时可以写 `domain_event_outbox`，EventBus 为空时 relay 不启动 | pending/failed 可能持续积压；当前 `/readyz` 没有一般 Outbox backlog component | 治理缺口 |
| GOV-CACHE-001 | cache catalog 有 11 个 AuthN/IDP/JWKS family，composition 只汇总 AuthN/IDP inspector | Suggest Redis 限流 key `iam:suggest:rl:*` 不在 catalog，失败时会 fail-open | 治理缺口 |
| GOV-CACHE-002 | 旧 `otp:{scene}:{phone}:{code}` code family 不在 catalog | 进一步支持旧 OTP code store 已退出主链路 | RET-CODE-003 的佐证 |
| GOV-AUDIT-001 | 审计 DDL、`AuditLogger` 端口与实际 writer/wiring 未闭合 | 删除会丢弃潜在合规能力，保留则产生“看似有审计、实际无数据”的错觉 | 待产品/合规决策 |

EventBus、readiness 和 Suggest cache governance 应分别立项。是否把一般 Outbox backlog 设为 required，需要先决定积压阈值、无 MQ 启动语义和误摘流量风险。

## 8. 数据库退役的强制门槛

任何候选表只有同时满足以下条件，才允许新增 forward `DROP TABLE` migration：

1. **仓库零引用**：运行时、脚本、job、bootstrap、报表、测试 fixture 和文档不再把它当事实源；
2. **跨仓零引用**：业务系统、seed/运维仓库和 SDK 无直连 SQL/接口依赖；
3. **生产零读写**：在覆盖业务周期的窗口内有网关/DB audit/Performance Schema 证据；计数器重启时间必须记录；
4. **数据一致性**：旧表到 canonical 表的主键、状态、软删除、关系和关键字段完成逐项对账；
5. **写入已停止**：先发布停止旧写/回填工具的版本，再经过观察窗口；
6. **依赖清空**：外键、trigger、view、event、procedure、账号权限和离线任务都已盘点；
7. **备份可恢复**：备份文件存在不够，需隔离恢复并完成关键数据断言；
8. **forward-only**：用新 migration 删除，不修改 000001–000018，不把 destructive down 当作可靠回滚；
9. **分批发布**：一次只退役一个同责任组，先 canary/单环境，再扩大；
10. **证据入账**：在本文记录环境、SHA、时间窗口、查询摘要、操作者和恢复证据链接。

仓库已提供统一的只读聚合入口：

```bash
export IAM_RETIREMENT_ENVIRONMENT=production
export IAM_RETIREMENT_IMAGE_SHA=sha256:replace-with-running-image-digest
export IAM_RETIREMENT_MYSQL_DEFAULTS_FILE=/absolute/path/to/private-mysql-client.cnf
export MYSQL_DBNAME=iam
make db-retirement-preflight > iam-retirement-preflight.tsv
```

`scripts/dbops/legacy-retirement-preflight.sh` 只执行聚合 `SELECT`，通过 MySQL defaults file 传递凭据，不输出 host、user、原始客户端错误或业务字段。它采集 server/version、migration 状态、10 张候选表的存在性/估算行数/大小/更新时间、Performance Schema I/O、FK/trigger/view/routine/event 依赖，以及四组旧表到 canonical 表的对账摘要。commit 默认读取当前 checkout，image SHA 由运行环境显式提供。

`table_rows` 是估算值；Performance Schema 计数只覆盖 server 启动或 summary 最近清零后的窗口，脚本会输出 uptime 和“零计数不能单独证明无使用”的提示。definition 不可见的 view/routine/event 会计入 opaque 数，任何 unavailable/opaque 都必须按证据不足处理。该入口已用 fake MySQL 验证只读查询、0600 临时凭据文件、清理和脱敏输出，但尚未取得生产运行结果。
