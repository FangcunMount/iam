# 目标模式：遗留资产安全退役实施提示词

> 状态：已实现 · 本文保留首批“不依赖生产删除授权”历史目标的原始边界；后续用户已分批授权 `000019–000022`，四个批次均已完成生产验收，实际范围和目标库证据以 canonical 退役台账为准。

## 1. 使用方式

在 IAM 仓库对应的 Codex 桌面应用、CLI 或 IDE 对话中输入 `/goal`，然后粘贴下面完整提示词。目标模式不会扩大当前 sandbox、审批或生产权限；缺少生产证据时仍应停在证据门前。

目标模式适合多步骤工作，但提示词必须同时写清结果、约束和完成标准，具体机制见 [OpenAI 长时任务说明](https://learn.chatgpt.com/docs/long-running-work)。本模板把数据库破坏性动作排除在本目标之外，避免“为了完成目标而删除表”。

## 2. 可复制提示词

```text
请在当前 IAM 仓库中完成一次“遗留资产安全退役”的可实施批次。

【目标结果】
以 docs/05-工程质量与运维/06-遗留资产兼容层与数据库退役审计.md 为唯一退役台账：
1. 完成其中所有状态为“可进入实现”的 RET-CODE-001..005；
2. 消除不依赖生产权限即可确认的 schema/bootstrap/Makefile truth-source 漂移；
3. 为历史 MySQL 表和待退役兼容面提供可复用、只读、secret-safe 的证据采集入口；
4. 保持外部可观察行为和明确兼容契约不变；
5. 更新退役台账和受影响的 canonical 文档，使代码、配置、迁移、测试和文档重新一致。

【权威输入】
- 首先完整阅读：
  - docs/05-工程质量与运维/06-遗留资产兼容层与数据库退役审计.md
  - docs/05-工程质量与运维/03-迁移发布与数据库运维.md
  - docs/03-基础设施/01-MySQL事务与迁移.md
  - docs/03-基础设施/02-Redis与缓存一致性.md
  - docs/03-基础设施/03-事件与Transactional-Outbox.md
  - docs/CONTRIBUTING-DOCS.md
- 当前代码、机器契约、runtime registration、配置、迁移和测试高于文档；若事实漂移，先记录证据并更新台账，不能按旧结论强删。

【绝对边界】
- 不执行任何生产写操作，不打印/复制凭据，不修改外部系统。
- 不执行 DROP/TRUNCATE/DELETE，不创建会删除候选表的 migration；本目标只允许只读数据库预检。
- 000001–000018 视为已发布历史，禁止修改；所有 schema 修复只能新增 forward migration，但本目标没有证据时不得新增 DROP migration。
- 保留并测试以下兼容面：
  1. REST auth_method="wechat" 到内部 wechat_mini 的归一；
  2. /health，以及 /healthz 和 /readyz 各自不同的探针语义；
  3. 历史数值 JWT tenant_id 到 canonical tenant domain 的归一和 SDK alias；
  4. 受测试保护的历史事件 payload shape；
  5. RemovedDataDir/RemovedSnapshot decode-only fail-closed tombstone。
- 不顺手实施 GOV-EVENT-001、GOV-CACHE-001、GOV-AUDIT-001；它们是独立治理/产品决策，不是本轮遗留删除。
- 保留用户已有 dirty worktree 变更；发现重叠时先区分归属，不覆盖、不 reset。
- deadcode、deprecated 名称和零静态调用只能生成候选，不能单独证明删除安全。

【实施方式】
先记录 git status、HEAD 和 baseline gate。随后一次只处理一个 RET-CODE 项；每项都执行：
1. 盘点定义、生产装配、REST/gRPC/SDK、配置、脚本、测试和跨包调用；
2. 用现有测试或最小表征测试锁定仍需保留的行为；
3. 删除最小闭合责任链，不留下只为旧测试存在的接口/DTO/key builder；
4. 运行 focused tests、architecture/contract gates；
5. 查看 diff，确认没有扩大范围；
6. 在退役台账记录结果、证据、验证和残余风险，再进入下一项。

RET-CODE 项的具体边界：
- RET-CODE-001：删除 internal/apiserver/domain/authz/model.go 兼容 facade；生产代码继续直接使用语义子包，保留防 facade 回流的架构护栏。
- RET-CODE-002：删除旧 Profile Editor、专属 DTO/接口和只验证旧用例的测试；当前 MyProfiles Patch/User Editor 行为必须保持。
- RET-CODE-003：删除 OTPCodeStore、OTPVerifierImpl.Put/Delete/VerifyAndConsume、otpRedisKey 和专属旧测试；保留 ChallengeRepository、OTP send gate 和 quota。
- RET-CODE-004：删除 OrgIDOrDefault；BusinessOrgID 的“无 claim 返回 ok=false”语义不变。
- RET-CODE-005：清理 IDP Router 旧登录路由注释、Makefile 的 make db-init 失效提示和无调用的 deprecated deploy-prepare；不要删除有效的 db-bootstrap/deploy/CD 入口。

truth-source 批次必须完成：
- 修复 configs/mysql/bootstrap.sql 在 migration 000014 之后重新写入 AuthZ tenant domain "1" 的问题；canonical DB domain 使用 "fangcun"，历史数值 JWT 兼容继续留在 token normalization，不靠数据库双域维持。
- 盘点 configs/mysql/schema.sql 的所有真实执行入口。选择“明确降级为不可执行参考并移除执行说明”或“由完整 migration 链生成并设置漂移门禁”中的更小可靠方案；不能继续把漂移副本描述为 migration 等价真相源。
- 修复与最终选择冲突的 README、Makefile、quick-start、测试和文档。
- 不修改 000001–000018 来让测试变绿。

数据库证据入口至少要能只读输出：
- server/version、schema_migrations version/dirty；
- 候选表存在性、估算行数、大小、更新时间；
- Performance Schema table read/write 计数及计数器生命周期提示；
- 外键、trigger、view、procedure/event 依赖；
- children -> profiles、guardianships -> profile_links、auth_accounts/auth_credentials_legacy -> canonical AuthN 表的对账摘要；
- 明确标注环境、时间、commit/image SHA，并避免输出认证材料、token、密码 hash、手机号、身份证或整行 PII。
若当前环境不存在生产连接，只交付并本地验证脚本/SQL，不伪造生产结果。

【验证门】
按改动范围至少运行并分别报告：
- go test ./...
- go vet ./...
- python3 scripts/check-route-contracts.py
- python3 scripts/check-docs-facts.py
- make docs-hygiene
- make docs-facts
- 涉及 migration/SQL 时运行 internal/pkg/migration focused tests 和可用的 MySQL 8 integration；未执行必须说明原因。
测试通过只证明当前 checkout 的对应范围，不得写成生产验收成功。

【停止条件】
遇到以下任一情况，保留实现目标为进行中，停止该候选的删除动作并给出证据和所需决定：
- 发现生产装配、外部调用方或未迁移配置；
- 需要 DROP/数据修复/生产写权限；
- 无法证明行为等价或数据对账；
- 兼容面是否下线需要产品、合规或调用方选择；
- baseline 已失败且无法区分既有问题与本轮回归。
停止一个被阻塞候选不妨碍继续处理其他独立、可安全完成的候选。

【完成标准】
只有同时满足以下条件才可宣布本目标完成：
1. RET-CODE-001..005 均已删除，或以具体新证据改为“保留兼容/待生产证据”，且台账已更新；
2. bootstrap 的 AuthZ 双域回流已消除并有测试；
3. schema.sql 不再是无门禁、可误执行的第二真相源；
4. 已交付并验证只读、secret-safe 的数据库退役预检入口，但没有创建或执行候选表 DROP；
5. 所有适用验证门通过，未执行项和残余风险明确；
6. 文档入口、canonical 事实和退役台账与最终代码一致；
7. 最终报告按“已完成 / 保留兼容 / 待生产证据 / 待产品决策 / 治理缺口”列出结果，并给出下一步所需的最小生产证据。
```
