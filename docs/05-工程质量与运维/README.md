# 工程质量与运维

> 状态：已实现 · 架构护栏及测试/验收正文已逐篇深化，其他质量/运维正文继续复核。

本目录把“代码正确”拆成多个独立证据面，并记录迁移、发布探针、备份恢复、安全日志和敏感凭据处置的操作边界。

架构正文区分责任划分与真实检测范围：67项现有规则包括直接import、AST声明、固定路径/原文和配置/契约检查；空import allowlist不消除testutil或collector豁免。原子解绑、会话撤销和Runtime重载各有不同合同，静态通过不替代事务、准入、运行与生产证据。

测试正文按结论、输入、后端、断言和执行记录组织证据：具体解释取消补偿、AfterCommit替身、SQLite单连接竞争、迁移Skip和指标断言，区分工作区增强与main已发布门禁，以及专项触发/选测/实际后端。下一篇继续迁移、发布与数据库运维；其余正文未因导航同步计为完成。

## 核心原则

```text
unit test passed
  != contract passed
  != build passed
  != migration passed
  != staging passed
  != production accepted
```

每一类结论只由对应证据支持；不可访问的生产数据必须写“未验证”，不能反推为正常。
