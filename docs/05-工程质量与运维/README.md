# 工程质量与运维

> 状态：已实现 · 架构护栏、测试/验收、迁移/发布、安全日志/凭据处置及文档治理正文已逐篇深化，遗留资产退役正文继续复核。

本目录把“代码正确”拆成多个独立证据面，并记录迁移、发布探针、备份恢复、安全日志和敏感凭据处置的操作边界。

架构正文区分责任划分与真实检测范围：67项现有规则包括直接import、AST声明、固定路径/原文和配置/契约检查；空import allowlist不消除testutil或collector豁免。原子解绑、会话撤销和Runtime重载各有不同合同，静态通过不替代事务、准入、运行与生产证据。

测试正文按结论、输入、后端、断言和执行记录组织证据：具体解释取消补偿、AfterCommit替身、SQLite单连接竞争、迁移Skip和指标断言，区分工作区增强与main已发布门禁，以及专项触发/选测/实际后端。

迁移/发布正文从已改变的状态判断重试与恢复：分别说明限定迁移入口、Fresh准备与归档、备份文件发布及部分恢复、status聚合谓词、跨仓制品坐标和配置/容器失败窗口。镜像回退、数据库恢复、消息及密钥处理各有责任和验收，命令退出码不能代替这些判断。

安全日志正文区分材料约束、实际出口与凭据失效效力：省略原值的适配器不保护Redis命令hook、指标或错误旁路；日志文件、容器输出、审计和发布副本各有责任。三个命令的独立目标、全文件删除、两条回执及部分失败按源码说明，确认短语不代替目标/停写/范围批准。

文档治理正文按读者问题确定完整owner，以Role更新的描述/行为及响应/持久化差别说明冲突处理，并串联主文、相邻摘要、图、证据与发布的更新闭环。main与工作区同名门禁、零选择/零命中、历史分类非原稿保全、图片摘要非生成出处分别限定；人工约定与自动化候选不混为已有保证。下一篇继续遗留资产退役，其余正文未因导航同步计为完成。

## 核心原则

```text
unit test passed
  != contract passed
  != build passed
  != migration passed
  != staging passed
  != production accepted
```

每一类结论只由对应证据支持；不可访问的生产数据必须写“未验证”，不能反推为正常。
