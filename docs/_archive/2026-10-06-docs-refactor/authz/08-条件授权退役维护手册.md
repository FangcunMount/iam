# 条件授权退役维护手册

> 状态：已实现 · 本轮代码已实现，生产数据切换与业务验收另行记录。

本轮将运营员与计划管理员的 assessments/retry 改为无条件动作授权；机构、受试者关系、测评状态和重试并发控制继续由 QS 执行。Scope 不在本轮范围内。

## 版本与证据

- 数据库迁移 35 只增加 `iam_condition_retirement_migrations` 清单表，不自动修改生产授权。
- `condition-authz-retire` 使用独立标识 `condition-authz-retire-v1`。原角色迁移清单、继承归档及历史 SQL 不修改。
- 暂留 constraint_set、attribute_schema 存储列；历史撤销记录保留原始内容。活动 REST 列表只读取有效授权。
- `pending` 可预演；`applied_unchanged` 可验证／幂等重跑；`applied_drifted` 只报告；`rolled_back` 不复用原标识自动迁移；`invalid` 必须停止。
- 完成状态查询不等于业务验收通过。原角色迁移状态出现漂移时，由本次清单解释，不改写旧 after_hash。

## 只读预演

使用现有 MYSQL_HOST、MYSQL_PORT、MYSQL_USERNAME、MYSQL_PASSWORD、MYSQL_DATABASE 环境变量；不把密码放进命令行或报告。执行者应在受限目录保存完整 JSON，工作流只输出摘要。

```sh
umask 077
mkdir -p /secure/condition-retirement
/app/iam-maintenance condition-authz-retire status > /secure/condition-retirement/status.json
/app/iam-maintenance condition-authz-retire preflight > /secure/condition-retirement/preflight.json
```

预演输出原始事实 fingerprint、授权变更、资源模式变更和逐主体 retry 来源变化。命中管理员通配或多个岗位并集时，added_origins 可为空。只自动处理已确认的两条来源规则；未知条件、非法 JSON、目录关系或 GrantKey 不符时停止。

## 切换

1. 完成三端测试及隔离 MySQL 演练，核对配置中的所有调用方。
2. 先发布维护工具兼容版本：原服务器继续使用旧授权实现，单独更新维护二进制及新增清单表。不得提前启动最终 IAM 服务器读取旧条件事实。
3. 在维护窗口暂停授权写入与受影响后台操作，重新预演；将结构化 fingerprint 与审核值比较。
4. 使用审核后的指纹执行 apply：

```sh
/app/iam-maintenance condition-authz-retire apply --writes-stopped --fingerprint "$REVIEWED_FINGERPRINT" > /secure/condition-retirement/apply.json
```

5. 部署最终 IAM、QS 和运营端，等待策略版本、Outbox、缓存和角色投影收敛；运行 verify。
6. 使用专用账号及测评验证运营员、计划管理员的两类来源重试，以及结果角色无重试权、越界拒绝和专业结果不可见。通过后恢复访问。

CLI 的 writes-stopped 是操作方声明，不会自动暂停其他写入者。事务内锁定策略版本并复核完整事实；暂停授权写入是必要前提。

## 回滚

暂停受影响操作，恢复兼容旧条件的服务器，按原 fingerprint 运行 rollback。后续事实变更会阻止自动回滚。回滚只撤销本次创建的目标 Grant，复用的原有 Grant 保留；恢复原条件 Grant 和资源模式，保留审计记录并发布更高 PolicyVersion。

QS 与运营端必须成组恢复，旧策略收敛前不可开放访问。清单表包含历史证据，不通过数据库 down 操作代替授权补偿。
