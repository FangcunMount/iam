# Private SDK build access

IAM depends on the private `FangcunMount/reliable-messaging` module. All dependency-fetching workflows use the shared private-modules action: CI lint/test/build, MySQL concurrency, production image build, role-model maintenance and reviewer maintenance. This does not grant permission to run maintenance or deploy.

An organization administrator supplies `IAM_MODULES_APP_CLIENT_ID` as an Actions variable and `IAM_MODULES_APP_PRIVATE_KEY` as an Actions secret visible to the IAM repository. Reuse an existing organization GitHub App if suitable. Install it on reliable-messaging with Contents: read. The action requests a short-lived installation token restricted to that repository and permission; the official token action revokes it at job completion. No personal token or repository visibility change is required. These names are the proposed integration contract, not evidence that organization credentials already exist.

The generated Git configuration is in RUNNER_TEMP with mode 0600. Authorization headers match only the SDK repository URLs, with or without `.git`. GIT_CONFIG_GLOBAL points to this temporary file for the job; existing user/global and repository configuration files are not modified. GOPRIVATE and GONOSUMDB select only the SDK. Every caller removes the temporary file in an always step. Missing App settings fail with a specific message before module download; a populated module cache is not proof of current authorization.

The production Docker builder gets the same file through BuildKit secret `private_git_config`, only during `go mod download`. It is never an ARG, ENV credential, authenticated URL or COPY input. The build context excludes `.git` and generated credential files, including checkout authentication. BuildKit secret contents are not part of the cache key: the first authorized release must perform a clean dependency download/build instead of relying only on an existing cache hit.

For an authorized local image build, keep the temporary read-credential config outside the repository and set `PRIVATE_MODULE_GIT_CONFIG` to its path. `make docker-build`, `make cd-image` and development Compose forward it as the build secret. Development Compose defaults the source to `/dev/null` so database-only operations can still parse without credentials; building the application requires the actual temporary config. These scripts do not mint credentials for local users. Delete the file when finished. No credential is needed in the running IAM container.

Offline checks: `python3 -m unittest discover -s scripts/ci -p 'test_*.py' -v` verifies exact Git URL scope, private permissions, failure cleanup and image-build argument forwarding with dummy data. It does not establish App installation, successful private module download or successful production image construction. Those remain release gates after administrator configuration.

References: [GitHub App token action](https://github.com/actions/create-github-app-token), [GitHub token permissions](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token), [BuildKit secrets](https://docs.docker.com/build/building/secrets/).
